# Installation and runtime identity

Use a compatible LAMMPS source tree (tested: 17 Apr 2024 Development).
The installer preserves existing source files before copying the validated pair.
No upstream GCMC, SGCMC, force or neighbor-building source file is patched.

```bash
bash install_to_lammps.sh /path/to/lammps
cmake -S /path/to/lammps/cmake -B /path/to/build-fast \
  -DCMAKE_BUILD_TYPE=Release -DBUILD_MPI=ON -DBUILD_SHARED_LIBS=ON \
  -DPKG_MC=ON -DPKG_MANYBODY=ON -DPKG_KSPACE=ON \
  -DPKG_MOLECULE=ON -DPKG_EXTRA-PAIR=ON
cmake --build /path/to/build-fast -j 4
export LD_LIBRARY_PATH="/path/to/build-fast:${LD_LIBRARY_PATH:-}"
mpirun -np 1 /path/to/build-fast/lmp -in examples/in.lj_fast
```

Use the actual executable name generated by your configuration (`lmp` or `lmp_mpi`).
The guard tests need KSPACE and MOLECULE so that rejection reaches the fix itself.
Match the MPI launcher to the MPI libraries used at build time; do not mix Intel MPI
with a conda MPICH library. Inspect `ldd` on both executable and shared library.
The marker printed during fix initialization is:

`Fix fast/swap RNG revision 20261020: rank-local seeds; serial stream unchanged`

The source hashes identify the code. A rebuilt binary normally has a new hash;
do not expect another compiler to reproduce the archived library bytes. No LAMMPS
Python wrapper or mpi4py is required for the CLI workflow. Python analysis requires
NumPy/SciPy/Matplotlib as listed in requirements.txt.
